      Technical details

      🔐 Lock a file with a password

      Turn any file into a locked file only your password can open.

      When should I use this?

      To send or store one sensitive file safely. Anyone with the password can open it — and there is no recovery if you forget the password.

      🔓 Unlock a file

      Open a locked (.svenc) file with its password.

      When should I use this?

      To open a file that was locked with “Lock a file”. You need the password it was locked with.

      🕵️ Hide data inside an image

      Encrypt a file with your password, then conceal it inside a PNG, BMP, or JPEG image.

      When should I use this?

      To tuck a small encrypted file inside an ordinary-looking image. The hiding place is not the protection — your password is. Concealment only makes the data less obvious; anyone who suspects it still cannot read it without the password.

      🔓 Reveal data hidden in an image

      Recover a file that was hidden with “Hide data”, using its password.

      When should I use this?

      To pull back out a file you (or someone) hid inside an image. You need the password it was hidden with.

      🔎 Detect hidden data

      Scan an image for signs of hidden data. Heuristic — it can flag suspicion, never prove innocence.

      When should I use this?

      For a quick, best-effort read on whether an image might carry concealed data (an appended file, LSB tampering). A low result means “nothing these tests caught” — not a guarantee the image is clean.

      ✍️ Sign a file

      Prove a file came from you and hasn't changed since.

      When should I use this?

      So others can confirm a file is genuinely from you. You sign with your private key; they check with your public key. First create a signing identity below.

      First, your signing identity

      Creates a keypair: a public key (.pub — share it so others can check your signatures) and a private key (.svkey — keep it secret; it's protected by a password).

      Sign a file

      Signs any file with your private key, writing <file>.minisig next to it.

      ✅ Check a signature

      Confirm a file was signed by a specific person and hasn't changed.

      When should I use this?

      When you received a file plus a signature and the signer's public key, and want to be sure the file is genuine and unaltered.

      🔢 Fingerprint a file

      Get a unique ID (BLAKE3) of a file's exact contents.

      When should I use this?

      To compare two copies of a file, or to record a value you can re-check later. Two files with the same fingerprint are identical.

      🕵️ Hide data inside a file Coming soon

      When you'd use it: to send something discreetly alongside a normal-looking file.

      Status: under evaluation — not available yet.

      💧 Tamper-proof an image

      Stamp an invisible, password-keyed mark into an image so you can later prove it hasn't been altered.

      When should I use this?

      To make an image self-verifying: the mark is invisible and tied to your password. Later, “Check for tampering” tells you whether the image is unchanged, and which areas were altered if not. The mark is fragile by design — re-saving as JPEG, resizing, or any edit breaks it. Works on PNG/BMP only. This proves integrity, not authorship.

      🔍 Check for tampering

      Verify a marked image against your password.

      🛡️ Check a file is unchanged

      Confirm a file still matches a fingerprint you were given.

      When should I use this?

      To check a download, backup, or shared file wasn't altered. You need the fingerprint the sender gave you (the same value Fingerprint a file produces). If you were given a signature file instead, use Check a signature.

      🧾 Verify a download

      Check a file against its published fingerprint and/or signature — in one step.

      When should I use this?

      When a file was published with a fingerprint (BLAKE3), a signature + the signer's public key, or both, and you want a single PASS/FAIL. Provide whichever you were given — at least one. (To check only one, Check a file is unchanged and Check a signature are the focused tools.)

      🧩 Split a secret

      Split a password, key, or note into pieces — any chosen number of them together restore it.

      When should I use this?

      To share trust across several people or places: no single piece reveals anything, but enough of them together rebuild the secret. You also get one payload file — keep it with the pieces; it's needed to recover. It's safe to copy, but don't lose it.

        🧩 Split a file

        Split a file into pieces — any chosen number of them together restore it.

        When should I use this?

        To back up a sensitive file (a keyfile, wallet, or document) across several locations. You get tiny piece files plus one payload file (the encrypted file); recovery needs the payload and enough pieces.

          🔗 Recover from pieces

          Rebuild a secret or file from enough of its pieces, plus the payload file.

          When should I use this?

          When you have at least the “needed to restore” number of pieces — as files (.svss) or pasted codes — together with the payload file they were made with.

          📷 Secure QR transfer

          Move Secret Sharing pieces between devices as QR codes — turn pieces into QR images, and recover from scanned/saved QR images.

          When should I use this?

          After Split a secret, to carry the pieces by phone camera or print instead of copy-paste. Each QR holds one piece — non-secret on its own; a threshold of them plus the payload file rebuilds the secret. The payload file is not in the QR codes; move it alongside them.

          🔗 Recover from QR images

          Rebuild a secret from enough QR images, plus the payload file.

          🔍 Inspect metadata

          See the hidden metadata a file carries — camera, location, author, software, timestamps.

          When should I use this?

          Before sharing a photo or document, to see what it quietly reveals about you — GPS coordinates, your name, the device, edit history. Reading is safe and never changes the file.

          🧹 Remove metadata

          Write a clean copy of a file with its embedded metadata stripped out.

          When should I use this?

          Before publishing a photo or document, to scrub identifying metadata (GPS, device, author, software). Your original is never touched — a new, cleaned copy is written.

          📑 Compare metadata

          See how two files' embedded metadata differs — what's added, removed, or changed.

          When should I use this?

          To confirm a cleaning step worked (compare original vs cleaned), or to see exactly what metadata two versions of a file carry. File names, sizes, and timestamps are ignored — only the real embedded metadata is compared.
